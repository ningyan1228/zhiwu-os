# CRM 编辑与跟进提醒对照

## 本轮修复

- CRM 列表与 360 统一读取最新人工沟通约定：按实际沟通日期、同日创建时间、记录 ID 排序。自动归档邮件不替代人工计划，补录旧记录不覆盖新记录。没有人工记录时才显示档案计划；最新记录未填下一步时明确为空，不制造默认行动。
- CRM 占位日期及已关闭跟进不计到期提醒。首页、跟进表、日历保留原有统一提醒模型。
- 跟进新增禁止界面重复提交；服务端对同客户、同日、同内容返回原记录。并发请求使用稳定主键防重；同内容但下一步不同返回冲突，需编辑原记录。原有重复记录不自动删除。
- 跟进列表分页读取完整历史，避免数据库默认返回上限导致客户最新记录遗漏。
- 请求超时覆盖读取响应正文；补充时间线最多等待 3 秒，避免已保存的跟进因附属时间线超时被误报失败。
- 询盘状态改为选择后明确点击“保存状态”，不依赖浏览器确认弹窗；保留版本冲突校验、保存反馈和刷新入口。认证及状态请求有超时边界。
- 新增客户归档和恢复入口，仅修改 archived_at；现有权限、关联邮件、项目、报价、跟进历史保持。
- 360 增加到邮件中心关联邮件入口，阶段选择标明立即保存。
- 导入页补充 JSON 格式、字段说明和模板。模板不含真实客户资料，不自动提交。

## 与 Muse 清单逐项对应

| 项目 | 实现和边界 |
|---|---|
| 1 保存无反馈 / 重复 | 客户表单已有禁用和错误提示；本轮跟进表单补齐防重复和服务端去重。尚需真实账号现场验收网络慢场景。 |
| 2 产品缺项 | 已有自由输入关注产品，优先于产品下拉；不伪造正式产品主数据。 |
| 3 / 13 下一步来源 | 本轮统一列表和 360；最新人工记录优先，档案计划为无记录时的后备，界面标明。 |
| 4 新建字段 | 已复用完整客户编辑表单，可填阶段、产品、行业、价值、优先级、应用、标签等。中文记忆名仍为账号浏览器偏好。 |
| 5 跟进日期 / 阶段 | 跟进新增记录历史；“今日工作 → 跟进表”提供完成并安排下次或关闭，编辑客户调整阶段。界面说明规则。 |
| 6 360 编辑 | 顶部编辑客户；跟进记录可编辑；报价、项目、供应商在对应管理入口编辑。历史聚合不是独立数据字段。 |
| 7 重复客户 | 提供归档和恢复；未自动合并或归档任何真实客户。 |
| 8 阶段 | 选择后立即保存，保存中禁用，有成功和错误提示。 |
| 9 邮件关联 | 360 可前往邮件中心，由用户选择邮件关联，不自动猜测。 |
| 10 日期粘贴 | 客户及跟进新增、记录编辑支持完整 YYYY-MM-DD 文本输入。 |
| 11 无邮箱 | 完整客户表单邮箱可留空，可填微信 / WhatsApp。 |
| 12 空日期 | API 接受空日期清除；客户表单允许留空，8 条已识别占位按待定。 |
| 14 询盘状态 | 本轮改为选择草稿和明确保存；本地合成数据交互验证通过，生产实际写入未在本轮执行。 |
| 15 导入说明 | 本轮补齐模板及字段说明；仍仅接受已验证的客户字段订正。 |

## 验证口径

模型测试覆盖日期边界、占位、关闭、同日排序、历史补录、自动归档排除。保存端点测试使用内存数据库替身，覆盖并发重试、重复返回、下一步冲突、非法日期和空内容。类型检查与生产构建另行运行。

本轮没有按文档直接改写任何客户公司名、询盘状态或沟通内容；没有删除或合并重复客户。合成测试不等于真实账号保存验收。邮件待回仍按既定同步基线和关联回复证据判定，不能将旧邮件数量直接作为待办。
