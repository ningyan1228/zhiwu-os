# 今日工作与跟进提醒口径

首页、跟进表、日历共用 `/api/followup-reminders` 快照，数据库按当前用户权限返回 CRM 与邮件资料。生产客户内容不进入前端构建。

## 字段

| 页面字段 | 来源 |
|---|---|
| 客户、联系人、产品 | customers.company_name / contact_person / product_interest |
| 下次跟进 | customers.next_followup_date；占位标记按待定显示 |
| 上次沟通 | followups 按 date、created_at 倒序第一条 |
| 下一步 | 最新人工 followups.next_action，排除邮件自动归档占位内容 |
| 来源 | 人工跟进 channel、email_id 或显式保存的 followup_source |
| 事由 | customers.followup_reason，由用户填写 |
| 邮件标记 | 权限内新邮件的 sender / received_at / subject，点击打开原文 |

## 日期与操作

北京时间自然日划分：负数逾期、0 今日、1–3 天近期、4–7 天本周、超过 7 天后续跟进；空值或无效日期待定。首页提醒只包含逾期、今日和未来 3 天。日历和跟进表包含全部真实日期。待定分组兼作资料待办，不另外统计一套数量。

完成本次跟进需要沟通结果、实际沟通日期，以及下一次日期和行动，或明确关闭。数据库一次事务保存记录和客户安排；版本、原日期和行动不匹配时拒绝旧表单，防止重复提交。关闭保留历史，可以重新安排。改日期可以清空。历史独立任务保留在折叠入口，不再混入客户跟进提醒。

指定占位记录仅作私有标记，不把日期规则写成“所有相同日期均排除”。原记录先备份；在 CRM 改成其他日期或在提醒表重新安排后解除占位标记。

## 邮件

首次启用记录当前账号可见的最后同步时间作为固定界线；无同步时间用启用时间。之后不会每次刷新移动界线。旧积压数量不变成新待办。

只处理有客户关联、界线以后收到且未处理的邮件。明确关联该邮件的人工跟进，或同邮箱 Sent 文件夹中匹配 In-Reply-To 的发送记录，可解除标记。邮件自动归档记录不视作人工已处理。没有可识别 Sent 文件夹或缺少有效日期/线程标识时，不推断已回复。不同邮箱权限保持原样，邮箱 2 不因此自动共享给其他账号。

## 图表

月度跟进按人工记录日期计数，排除自动邮件归档。任务完成与承诺兑现按明确完成日期计数。客户阶段是当前分布，不表示转化率或当月新增；不推算收入。

## 验证

`node scripts/test-followup-model.cjs` 验证日期边界、无效日期、占位、关闭和下一步来源。迁移在隔离 PostgreSQL 验证完成、关闭、历史保留和过期表单拒绝；生产接口按普通用户会话读取，并拒绝匿名请求。真实邮件发送证据取决于邮件服务器提供的 Sent 标记和线程头，不能把未取得证据当作已发送。

## 已有沟通的旧日期（2026-11-20 更新）
原日期早于今天，且最新人工沟通日期不早于原日期、不晚于今天时，显示“跟进日期待核”。不自动视为原事项完成，不修改数据库原日期，不推测新日期。自动归档邮件不能触发此判断。
首页单独提供待核数量和列表，红色逾期计数、紧急列表及铃铛仅包含未进入待核的逾期。CRM 与跟进表采用同一判断；日历仍保留原日期，并标注待核。用户核对后可在跟进表“核对日期”选择真实新日期或清空转待定；完成和关闭仍需明确操作。
